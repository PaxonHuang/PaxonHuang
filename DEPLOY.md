# Cloudflare Pages Deployment

This project deploys to Cloudflare Pages via **direct Git integration** — push to `main` and Cloudflare builds & deploys automatically. No API tokens, no GitHub Actions needed.

## Live URLs

- **Production**: <https://paxonhuang.pages.dev>
- **Latest preview**: <https://a7c8921a.paxonhuang.pages.dev>

## Architecture

```
GitHub (main branch)
       │  (push)
       ▼
Cloudflare Pages
   │  npm ci
   │  npm run build
   ▼
dist/  ──►  https://paxonhuang.pages.dev
```

### Files involved

| File | Purpose |
|------|---------|
| `astro.config.mjs` | Astro config; build output → `dist/` |
| `package.json` | `npm run build` runs `astro build` |
| `wrangler.jsonc` | Wrangler project metadata (project name = `paxonhuang`) |
| `output` branch | Generated by `snake.yml` for the GitHub contribution snake; **not** used by Cloudflare Pages |

## One-time setup

If you ever need to re-attach this repo to a fresh Cloudflare Pages project:

1. **Cloudflare Dashboard** → Workers & Pages → **Create application** → Pages → **Connect to Git**
2. Select `PaxonHuang/PaxonHuang`
3. Project name: **`paxonhuang`** (must match `wrangler.jsonc`)
4. **Production branch**: `main` (NOT `output` — that's the snake-svg branch)
5. **Build settings**:
   - Build command: `npm run build`
   - Build output directory: `dist`
   - Root directory: *(leave empty)*
6. **Environment variables** (optional):
   - `NODE_VERSION` = `22`

That's it. No secrets, no tokens, no GitHub Actions.

## Triggering a deploy

Just push to `main`:

```bash
git push origin main
```

Cloudflare will:
1. Detect the push
2. Clone the repo at the latest `main` commit
3. Run `npm ci && npm run build`
4. Upload `dist/` to the Pages project
5. Roll out to the production URL

Typical build time: **~30-60 seconds**.

## Preview deployments

Every push to a non-`main` branch (or every PR) gets a unique preview URL:
- `https://<commit-hash>.paxonhuang.pages.dev` for branches
- PR comments auto-post the preview link

## Custom domain

To attach a custom domain (e.g. `paxonhuang.com`):

1. Cloudflare Dashboard → Workers & Pages → `paxonhuang` → **Custom domains**
2. Add the domain — DNS auto-configures if the zone is already on Cloudflare.

## Troubleshooting

### "Could not read package.json: ENOENT"

The build is checking out the wrong branch. The **Production branch** in Cloudflare Pages must be `main`, not `output` or `gh-pages`.

Fix: Dashboard → Workers & Pages → `paxonhuang` → **Settings** → **Builds** → **Production branch** = `main`.

### "npx failed with exit code 1"

Click into the failed run to see which step failed. Common causes:
1. **Build error** — check the build log; usually a missing dependency or syntax error
2. **Node version mismatch** — set `NODE_VERSION=22` in environment variables
3. **Out of memory** — Astro builds can use a lot of RAM; the default 1 GB Pages limit is usually enough, but increase to 2 GB if needed in Settings → Builds → **Compatibility flags**

### Build succeeds but site shows old content

Cloudflare aggressively caches. Force a hard refresh (Cmd+Shift+R / Ctrl+Shift+R) or add a cache-buster query param (`?v=1`).

### Roll back a deployment

Dashboard → Workers & Pages → `paxonhuang` → **Deployments** → click a previous successful deployment → **Rollback to this deploy**.
